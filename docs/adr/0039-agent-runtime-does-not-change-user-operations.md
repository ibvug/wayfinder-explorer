# Agent 运行时抽象不改变既有用户操作

把逻辑 Agent 会话绑定到 Codex Thread 或未来其他运行时，只是 Explorer 内部结构变化，不能改变探索者已经使用的地图交互和确认流程。开始绘图中的顶层顺序只有先建立目的地、再建立起点，随后才形成首图草案；取证边界和定向取证属于建立起点的内部对话，不得成为与目的地、起点并列的步骤，也不得增加“确认取证范围”操作。确认目的地和确认起点分别是建立对应端点时对当前草案确切内容的明确接受，不是新阶段，也不能由 Agent 从普通对话回复中推断。开始绘图、开始探索、发送回答、确认目的地、确认起点、形成草案、继续讨论、暂存草案、预览地图变化和确认写回仍保持各自含义与入口。专用地图修改能力只在内部把 Agent 提案转换为经过版本校验的预览和原子写入；它不增加一套由 Agent 运行时自行定义的用户操作，也不能用普通工具审批替代既有的地图预览与明确确认。未来更换 Agent 运行时也必须满足同一用户操作契约。
