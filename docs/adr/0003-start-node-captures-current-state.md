# 起点节点记录当前现状

每次目标探索在绘制首图前依次建立目的地和起点：先把模糊意图建立为目的地，再确认这次旅程真正要改变的对象及其现状，二者不是并行确认。建立起点时，地图 Agent 在同一段连续对话中先了解探索背景和可作为证据的资料，只在约定边界内定向检查相关事实，并以确切证据版本形成一份内容明确的起点草案；草案正文直接呈现可独立理解的统一现状摘要，形成依据通过可展开的证据引用查看。草案及其证据版本随地图 Agent 会话持久保存和恢复，在确认前可以继续讨论和修改，但进程恢复不会使它成为地图事实。确认起点时，Explorer 必须重新校验草案依据的证据版本；任何相关变化都会使旧草案失效，旧草案保留为历史但不能继续确认，地图 Agent 必须基于最新证据重新核对并形成新草案。探索者通过 Explorer 的确认起点操作接受仍有效草案的确切内容后，Explorer 立即把它独立保存并冻结为起点节点，随后才允许形成首图草案，普通对话回复不产生这个确认。已确认起点不能重新打开或覆盖；若它不能作为这次探索的真实历史基线，则建立新的目标探索，而不是改写原起点。项目、分支、资料和工具观察只是证据，除非它们本身就是要被改变的对象，否则不能代替起点。只有探索者明确确认的对象规则、认识和约束，以及对象当前真实存在的状态才能进入起点；这些内容必须浓缩为一份统一的现状摘要，无需先打开形成原因或证据即可理解对象当前的核心状态，而不是按“规则／实现”或证据来源分栏，也不是复制完整领域文档。Agent 推断、假设、未决问题、未来方案和后续任务继续留在对话、议题或迷雾中；路径、提交、文件数量、测试数量等形成依据只保留在证据引用中，不写入起点正文。取证范围只是建立起点的内部约束，不是独立用户阶段或操作。起点是确认时的固定历史基线，只保存所改变对象的现状摘要和证据指针；后续首图只能引用它，不能重新生成或改写，环境变化也不会静默改写它。这样后续议题由真实现状与目的地之间的差距产生，而不会默认从空白开始、把仓库盘点误作起点或盲目扫描整个环境。
